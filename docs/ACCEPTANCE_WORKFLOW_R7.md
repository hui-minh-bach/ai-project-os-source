# R7 acceptance boundaries

## Supported source workflows
- Website/source: named team -> analysis/Council -> explicit specification/test-mode approval -> actual workers/review/test/Git -> source ZIP. Tested with synthetic AI generating a small static site; arbitrary business requirements are not thereby verified.
- Cloud web handoff: existing R6 static/Vite/Next adapter preserved; extra scoped cloud/cost approval; URL + local QR + source appears in the unified product panel. Verified with synthetic cloud APIs only.
- News article: selected stored source -> author -> different reviewer -> real saved article, caption/hashtags and Markdown; user receipt does not post to social platforms. Text review is not independent factual verification of the outside world.
- Caption-only video: explicit choice -> author/reviewer -> real FFmpeg 1280x720 MP4 + SRT -> preview/download and local receipt. It has no narration and no generated cinematic imagery.
- Narrated video: installed voice/API prerequisites must pass. Optional Windows SAPI adapter not physically tested here; no commercial voice quality claim.
- Radar: real storage/parser/query logic and UI; provider failures visible. The build environment could not resolve the public RSS host; public coverage/availability remains unverified.

## Evidence rules
Read verification.json for fresh counts. 90 tab/theme/viewport combinations are navigation checks, not 90 full functional acceptances. HTML/CSS/classic scripts run in Linux Chromium via an authenticated local API bridge; ES-module 3D is not loaded. No private real-account tokens or customer records are included. A file hash proves identity, not quality or a digital signature. Release-readiness must remain false until its real-world gates are met.
