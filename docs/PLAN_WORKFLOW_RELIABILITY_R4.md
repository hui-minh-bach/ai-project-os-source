# AI Project OS R4 - execution reliability plan

## 1. Preserve the approved application
Keep the complete R3 3D room, names, geometry, animation and brightness controls. Snapshot all file hashes. Work on a new source copy and never touch customer data.

## 2. Repair execution, not visual theatre
- Route each project request through a bounded dispatcher. Primary, explicit backup, same-provider peers, then eligible connected text models with their OWN catalog model IDs.
- Classify quota, temporary outage, timeout, authentication, unavailable model, empty/malformed result and unsupported text-only bridge separately from cancellation, safety policy, changed credentials, vault lock or bad input.
- Preserve the same spec/task/current workspace/tool history at each handoff. Only a validated response may perform a tool operation. Never rerun a completed write just because a provider changed.
- Record failed attempts and the actual responding account/model. Keep a short circuit cooldown and a total call budget. Never loop infinitely or request new privileges.
- Keep approval/independent review gates and preserve the current worktree during an in-request handoff.

## 3. Wire the workflow and recovery
- Replace the intake button's navigation-only success with real analyze/council processing, stopping at the existing human specification gate.
- Let the ready-task runner continue dependency waves rather than silently stop after its first batch. Failed dependencies remain explicit, and a task executes at most once per batch invocation.
- Validate news card/video/idea input before project creation; snapshot news inputs so later feed changes do not break a run.
- Retry failed production steps in the SAME run, preserving completed AI/script/output stages. Do not automatically retry uncertain external publication.
- Add visible assignment/failover events, actual error status, and retry actions. Keep AI task simulation separate.

## 4. Prove and package
- Test primary 429/500/timeout/401/empty output; different provider/model failover; all unavailable; model inventory checks; no secret in journal; requester cancellation; reviewer separation.
- Exercise real HTTP server and browser intake, project tasks, failover feed and retry. Use local fixture providers, never fake these as live vendor output.
- Run full regression + syntax checks; verify protected 3D files; inspect UI screenshot; verify ZIP integrity.
- Deliver one full source archive with launch instructions, this plan, checkpoint and evidence.

## Completion boundary
Source and isolated-runtime validation do not certify Windows GPU/FPS, installed vendor CLIs, live provider quotas or production publishing. No such claims without actual evidence.
